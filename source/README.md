# mknkDesktopCats 1.9.8 — ネコシステム社

オニャンコポンの腹毛と歩行を調整したWindows x64用デスクトップペットです。画像取り込みと再生の方針は `AGENTS.md` にあります。

`VERSION` を元に `tools/build_version.py` がC用の表示ヘッダー、WindowsのVERSIONINFOリソース、配布用VERSION.txtを生成します。

猫または通知領域アイコンを右クリック→「バージョン情報…」で製品版番号を表示します。EXEのプロパティ→詳細には製品バージョン1.9.8・ファイルバージョン1.9.8.0を格納します。

## ソース画像と取り込み

| 猫 | 原画 | セル構成 |
| --- | --- | --- |
| ゆりちゃん | `art_source/reference/yuri_walk_sheet.jpg` | 2048×1024、4列×2行 |
| オニャンコポン | `art_source/reference/onyankopon_walk_sheet.jpg` | 2048×1012、4列×2行 |

原画は添付JPEGのバイト列そのものです。`tools/import_reference.mjs` でSHA-256を照合してから取り込みます。

- 固定列原点はx = 0 / 512 / 1024 / 1536、各512px幅です。
- 原画の上下段の余白に合わせて、猫ごと・段ごとに固定の行原点と取り込み高さを使います。同じ段の4コマは同じ行設定です。
- 各切り出しを512×512の透明キャンバスへ収め、全16コマ共通の倍率425/512でキャンバス全体を425×425へ縮小します。
- 座標・余白・倍率・元画像のハッシュは `build/assets/reference-import.json` と配布の `preview/reference-import.json` に記録します。
- 切り出し外に猫を欠落させないこと、各列のコマ順と共通倍率を検証します。

緑背景からアルファを推定し、全コマに共通の縮尺で取り込みます。オニャンコポンはF04を基に胴体と脚のテクスチャをそろえ、肩と股関節から脚を動かすメッシュで1周24姿勢を描画します。取り込みの記録は `reference-import.json` の `frames`、描画用のハッシュと各足・関節の位置は `walkCorrection` に入ります。

前足は持ち上げる高さと腕の長さの設定を調整し、肘を浅く曲げた姿勢で前へ運びます。F01・F02の脚の太さ、歩幅と接地に加え、両前足の最大の曲げ角を検査します。

着地順はネコの歩行で観察される、後ろ足から同じ側の前足への順序を参考にしました。[四肢の着地順の観察](https://pmc.ncbi.nlm.nih.gov/articles/PMC4044364/)

後ろ足の膝の曲げ角を抑え、かかとの関節を別に動かします。蹴り出しで足裏をつま先の周りに傾け、足を戻すときの持ち上げを低くしています。膝と足首が異なる時点で曲げ伸ばしへ移る様子を参考にしました。[後ろ足の関節の観察](https://pmc.ncbi.nlm.nih.gov/articles/PMC8863752/)

組み込みのImageGenには、オニャンコポンのF04の体格と姿勢を保ち、茶トラの縞と陰影が脇腹から毛先まで続くように、ゆりちゃんと同程度に腹毛を広げるよう指定しました。生成した素材を `art_source/overlays/onyankopon_walk_fur.png` に保存し、顔と尻尾は元のF04から取り込んでいます。

透明度の正解データはないため、JPEGの輪郭の緑かぶりや圧縮の影響を完全に取り除ける保証はありません。描画時は乗算済みBGRAへ変換し、左向きはセル全体の左右反転です。初期位置・呼び戻し位置は従来の349px基準を使い、保存済みの位置は引き継ぎます。

## 復元した6姿勢

`art_source/rest/yuri_green.png` と `onyankopon_green.png` は、v1.3.1に同梱されていた元の姿勢シートです。`tools/import_rest.mjs` で原画のSHA-256を照合し、各姿勢の全身を含む明示した矩形から透過画像を取り込みます。元の等分セルを超えていた耳・前足も含めて復元します。

身体を部分変形せず、全身の一様な倍率と位置で425×425キャンバス・接地下端349pxへ合わせます。休息のRGBは透過輪郭の緑かぶり除去と全身の縮小処理を含み、歩行は今回のJPEGから所定の透明化・縮小処理を適用した結果と照合し、休息はv1.9.2の既存出力との一致を照合します。切り出し・倍率・元画像のハッシュは `build/assets/rest-import.json` に記録します。

| 組み込み番号 | 動作 |
| --- | --- |
| 0〜7 | 歩行の基本8姿勢 |
| 8 | 座る |
| 9 | 眠る |
| 10 | 伸び |
| 11 | 前足を上げる |
| 12 | ジャンプ姿勢 |
| 13 | 見回す |

休息は各1枚の全身姿勢です。ジャンプは全身の上下移動、走る動作は歩行ループの高速再生です。画像束の末尾にオニャンコポン用の中間姿勢16枚を格納します。

`src/pet_behavior.h` の独立した行動時計は50ms単位です。旧版の自律行動の出現割合・時間を基に、睡眠後には伸びをします。一時停止・非表示・ドラッグ中は残り時間を保持します。

## 再生と描画

- `src/reference_walk.h` が歩行中の2匹それぞれのF01〜F08を管理します。休息時には歩行時計を止め、対応する復元画像へ切り替えます。
- 目標周期は、ゆっくり2400ms、ふつう1200ms、元気800msです。オニャンコポンは通常の1周を50ms間隔の24姿勢に分けます。
- 歩行・走行・ジャンプ中は33msの要求タイマーで更新します。2匹とも静止姿勢のときは200msへ切り替えます。歩行中は姿勢を保持している間も横移動します。Windowsの実際のタイマー精度は環境に依存します。
- 1周の移動量は表示幅256px換算でゆりちゃんが48px、オニャンコポンが112pxです。オニャンコポンの前足の振り幅は425px素材で約119pxとなり、ゆりちゃんの約120pxに近づいています。
- `src/onyankopon_walk.h` は歩行時計から中間姿勢を選びます。一時停止・非表示・ドラッグ中は現在の姿勢を保持します。
- 左右の描画キャッシュを再利用し、画像内容が同じ場合は位置だけを更新します。

既定224px時の全姿勢キャッシュは `44枚×2方向×224×224×4` = 17,661,952 bytes（約16.84MiB）です。元画像の展開バッファは `44枚×425×425×4` = 31,790,000 bytes（約30.32MiB）です。

## ビルド

Linux上のGCC、GNU binutils（`ld -V`に`i386pep`）、Python 3、Node.js、Sharp 0.35.4を使います。追加のWindows SDKは不要です。

```bash
npm install
bash build.sh
bash tests/run_tests.sh
node tools/build_reference_viewer.mjs . ../preview/walk-check.html
```

`build.sh` は `CODEX_PRIMARY_RUNTIME_NODE` と `CODEX_PRIMARY_RUNTIME_NODE_MODULES` が設定されていれば利用します。ビルド出力は `dist/mknkDesktopCats.exe` です。

動画は素材の生成後に `python3 tools/build_preview_video.py` で作成できます。PythonのPillowとffmpegが必要です。配布の `preview/walk-preview.mp4` は標準224pxで歩行→座る→眠る→伸び→歩行を表示します。

## 検証

テスト対象は、原画JPEGのハッシュ、固定座標・共通倍率による取り込み、推定アルファ、8コマの順序とループ、3速度、停止・非表示・ドラッグ、左右の描画、位置のみの更新、猫別の初期配置、Windows x64 PEの構造です。所定の処理から独立に再構成したRGBAを表示用画像と比較し、表示用画像とEXE内の素材の一致を検査します。元JPEGと縮小後のRGB完全一致を主張する検証ではありません。

`tests/verify_onyankopon_walk.mjs` は胴体の毛色、F01・F02の前足の太さ、腹毛の深さ、前足と後ろ足の接地を検査します。`tests/verify_preserved.mjs` は既存の動作・休息取り込み処理と休息12枚のPNGを照合します。結果は `tests/validation-report.json` と配布ルートの `BUILD-REPORT.txt` にあります。

`tests/verify_version.py` は最終EXEのリソースツリーを独立して読み、RVA・VERSIONINFO・数値と文字列の版番号・日本語/Unicode情報を検証します。歩行画像は今回の新素材、休息画像はv1.9.2の既存素材を照合します。`tests/version_ui_test.c` はバージョン情報表示の選択・文面・通知フラグ・既存状態への無変更を検査します。

描画テストはWindows APIスタブを使ったCコードの検証です。Windowsでは起動とオニャンコポンの歩行を確認しました。CPU使用率は未測定です。HTMLプレビューは素材と再生の確認用です。

実行中の猫を画面取得ツールで確認する場合は、起動プロセスに `MKNK_DESKTOP_REVIEW=1` を設定します。ウィンドウを画面取得対象として表示し、初期の歩行時間を延ばします。v1.9.8ではこの表示を用いて同じEXEの前足を持ち上げる姿勢と複数周のループを連続で確認しました。
