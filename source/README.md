# mknkDesktopCats 1.9.3 — ネコシステム社

今回の添付JPEG 2枚へ歩行8コマのみを差し替え、座る・眠る・伸び・反応・ジャンプを引き継ぐWindows x64用デスクトップペットです。ご指定のv1.8.1そのものは取得できず、取得できたv1.9.2を基にv1.9.3として更新しています。画像取り込みと再生の方針は `AGENTS.md` にあります。

`VERSION` を元に `tools/build_version.py` がC用の表示ヘッダー、WindowsのVERSIONINFOリソース、配布用VERSION.txtを生成します。ZIP名と展開フォルダー名も版番号を含めます。EXE名・設定保存先・既存モーション・休息12画像は引き継ぎ、歩行16画像を更新します。

猫または通知領域アイコンを右クリック→「バージョン情報…」で製品版番号を表示します。EXEのプロパティ→詳細には製品バージョン1.9.3・ファイルバージョン1.9.3.0を格納します。

## ソース画像と取り込み

| 猫 | 原画 | セル構成 |
| --- | --- | --- |
| ゆりちゃん | `art_source/reference/yuri_walk_sheet.jpg` | 2048×1024、4列×2行 |
| オニャンコポン | `art_source/reference/onyankopon_walk_sheet.jpg` | 2048×1012、4列×2行 |

原画は添付JPEGのバイト列そのものです。`tools/import_reference.mjs` でSHA-256を照合してから取り込みます。

- 固定列原点はx = 0 / 512 / 1024 / 1536、各512px幅です。
- 原画の上下段の余白に合わせて、猫ごと・段ごとに固定の行原点と取り込み高さを使います。同じ段の4コマは同じ行設定です。
- 各切り出しを512×512の透明キャンバスへ収め、全16コマ共通の倍率425/512でキャンバス全体を425×425へ縮小します。
- 座標・余白・倍率・元画像のハッシュは `build/assets/reference-import.json` と配布の `preview/reference-import.json` に記録します。
- 切り出し外に猫を欠落させないこと、各列のコマ順と共通倍率を検証します。

緑の背景からアルファを推定し、脚の間の緑も取り除きます。黒い模様を黒色キーで透過する処理はありません。原画JPEGは再圧縮せず保持します。表示用画像には透明化と全身の縮小が入るため、原画のRGB値・解像度とは一致しません。脚の部位変形、猫ごと・コマごとの倍率調整、各コマの位置合わせ、中間姿勢の追加は行いません。原画に含まれる姿勢差とF08→F01のつながりはそのまま使います。

透明度の正解データはないため、JPEGの輪郭の緑かぶりや圧縮の影響を完全に取り除ける保証はありません。描画時は乗算済みBGRAへ変換し、左向きはセル全体の左右反転です。初期位置・呼び戻し位置は従来の349px基準を使い、保存済みの位置は引き継ぎます。

## 復元した6姿勢

`art_source/rest/yuri_green.png` と `onyankopon_green.png` は、v1.3.1に同梱されていた元の姿勢シートです。`tools/import_rest.mjs` で原画のSHA-256を照合し、各姿勢の全身を含む明示した矩形から透過画像を取り込みます。元の等分セルを超えていた耳・前足も含めて復元します。

身体を部分変形せず、全身の一様な倍率と位置で425×425キャンバス・接地下端349pxへ合わせます。休息のRGBは透過輪郭の緑かぶり除去と全身の縮小処理を含み、歩行は今回のJPEGから所定の透明化・縮小処理を適用した結果と照合し、休息はv1.9.2の既存出力との一致を照合します。切り出し・倍率・元画像のハッシュは `build/assets/rest-import.json` に記録します。

| 組み込み番号 | 動作 |
| --- | --- |
| 0〜7 | 指定画像の歩行8コマ |
| 8 | 座る |
| 9 | 眠る |
| 10 | 伸び |
| 11 | 前足を上げる |
| 12 | ジャンプ姿勢 |
| 13 | 見回す |

休息は各1枚の全身姿勢です。ジャンプは全身の上下移動、走る動作は同じ歩行8コマの高速再生です。新たな中間姿勢は生成していません。

`src/pet_behavior.h` の独立した行動時計は50ms単位です。旧版の自律行動の出現割合・時間を基に、睡眠後には伸びをします。一時停止・非表示・ドラッグ中は残り時間を保持します。

## 再生と描画

- `src/reference_walk.h` が歩行中の2匹それぞれのF01〜F08を管理します。休息時には歩行時計を止め、対応する復元画像へ切り替えます。
- 目標周期は、ゆっくり2400ms（300ms/コマ）、ふつう1200ms（150ms/コマ）、元気800ms（100ms/コマ）です。
- 歩行・走行・ジャンプ中は33msの要求タイマーで更新します。2匹とも静止姿勢のときは200msへ切り替えます。歩行中は姿勢を保持している間も横移動します。Windowsの実際のタイマー精度は環境に依存します。
- 移動量は表示幅256px換算で1周48pxの設定値です。原画から計測した生体の歩幅ではありません。
- タイマー遅延時はコマを飛ばしません。一時停止・非表示・ドラッグ中は現在のコマを保持します。
- 表示サイズに合わせた左右の描画キャッシュを再利用します。同じコマでは位置だけを更新し、位置も変わらなければ画像転送を省きます。

既定224px時の全姿勢キャッシュは `2匹×2方向×14枚×224×224×4` = 11,239,424 bytes（約10.72MiB）です。元画像展開後は `2匹×14枚×425×425×4` = 20,230,000 bytes（約19.29MiB）です。これは各画像バッファの容量で、アプリ全体の実測メモリ使用量ではありません。

## ビルド

Linux上のGCC、GNU binutils（`ld -V`に`i386pep`）、Python 3、Node.js、Sharp 0.35.4を使います。追加のWindows SDKは不要です。

```bash
npm install
bash build.sh
bash tests/run_tests.sh
node tools/build_reference_viewer.mjs . ../preview/walk-check.html
```

`build.sh` は `CODEX_PRIMARY_RUNTIME_NODE` と `CODEX_PRIMARY_RUNTIME_NODE_MODULES` が設定されていれば利用します。ビルド出力は `dist/mknkDesktopCats.exe` です。

動画の再作成は任意です。ビルド後に `python3 tools/build_preview_video.py` を実行します。PythonのPillowとffmpegが必要です。配布の `preview/walk-preview.mp4` は歩行→座る→眠る→伸び→歩行を表示する素材プレビューです。

## 検証

テスト対象は、原画JPEGのハッシュ、固定座標・共通倍率による取り込み、推定アルファ、8コマの順序とループ、3速度、停止・非表示・ドラッグ、左右の描画、位置のみの更新、猫別の初期配置、Windows x64 PEの構造です。所定の処理から独立に再構成したRGBAを表示用画像と比較し、表示用画像とEXE内の素材の一致を検査します。元JPEGと縮小後のRGB完全一致を主張する検証ではありません。

`tests/verify_preserved.mjs` は以前の動作コード・休息取り込み処理・休息12枚のPNGバイト列とRGBAの維持を検査します。今回の変更前であるv1.9.2からの継続も確認します。結果は `tests/validation-report.json` と配布ルートの `BUILD-REPORT.txt` を参照してください。

`tests/verify_version.py` は最終EXEのリソースツリーを独立して読み、RVA・VERSIONINFO・数値と文字列の版番号・日本語/Unicode情報を検証します。歩行画像は今回の新素材、休息画像はv1.9.2の既存素材を照合します。`tests/version_ui_test.c` はバージョン情報表示の選択・文面・通知フラグ・既存状態への無変更を検査します。

描画テストはWindows APIスタブを使ったCコードの検証です。Windows実機での起動・操作とCPU使用率の測定はこの環境では未実施です。HTMLプレビューは素材と再生の確認用です。
